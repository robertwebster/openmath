# Activity networks — worked examples

## Example 1: Reading a precedence table

A small construction project has the following activities and their immediate predecessors.

| Activity | Description | Duration (days) | Immediate predecessors |
|---|---|---|---|
| A | Site preparation | 3 | — |
| B | Order materials | 2 | — |
| C | Lay foundations | 4 | A |
| D | Deliver materials | 3 | B |
| E | Build frame | 5 | C, D |
| F | Fit roof | 2 | E |

Identify: (a) which activities can start immediately, (b) what E depends on, and (c) which activity leads to the finish.

<WorkedExample>
  <Step>(a) Activities with no predecessors can start at time zero. Reading the table: A and B both have a dash in the predecessors column — they can start immediately.</Step>
  <Step>(b) Activity E lists C and D as immediate predecessors. E cannot start until both the foundations are laid (C) and the materials have been delivered (D).</Step>
  <Step>(c) Activity F is not listed as a predecessor of any other activity, so F leads directly to the finish of the project.</Step>
</WorkedExample>

## Example 2: Identifying a dummy activity

Two activities in a project share a complicated dependency:

- Activity C depends on A only.
- Activity D depends on both A and B.

Explain why a dummy activity is needed and what it represents.

<WorkedExample>
  <Step>In an activity-on-arrow network, each activity is drawn as an arrow between two nodes. To show that D requires both A and B, the tail of D must connect to the head-nodes of both A and B.</Step>
  <Step>But if we draw C and D sharing the same pair of end-nodes (because both involve A), the diagram incorrectly shows that C also requires B.</Step>
  <Step>The solution is to draw A ending at node 2, then draw a dummy activity (dashed arrow, 0 days) from node 2 to node 3, and have B also end at node 3. D then starts from node 3. C starts from node 2.</Step>
  <Step>The dummy arrow carries no duration. It simply says: "before D can start, you must wait for both A (via node 2 → node 3 dummy) and B (directly into node 3)." C correctly depends only on A (starting from node 2, before the dummy).</Step>
</WorkedExample>

## Example 3: Finding activities with no successors

For the project below, identify which activities lead directly to the finish node.

| Activity | Immediate predecessors |
|---|---|
| A | — |
| B | — |
| C | A |
| D | A, B |
| E | C, D |
| F | B |
| G | E, F |

<WorkedExample>
  <Step>An activity leads to the finish if no other activity lists it as a predecessor.</Step>
  <Step>Check each activity in turn:
  - A: listed as predecessor of C and D — not a finish activity.
  - B: listed as predecessor of D and F — not a finish activity.
  - C: listed as predecessor of E — not a finish activity.
  - D: listed as predecessor of E — not a finish activity.
  - E: listed as predecessor of G — not a finish activity.
  - F: listed as predecessor of G — not a finish activity.
  - G: not listed as a predecessor of any activity — G leads to the finish.</Step>
  <Step>Only activity G leads directly to the finish node. The project ends when G is complete.</Step>
</WorkedExample>
